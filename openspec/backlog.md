## Подсказчик ошибок SQL (без ИИ)

- PGlite возвращает сообщение Postgres и позицию ошибки.
- Превратить их в понятный русский текст по правилам: «пропущена запятая
  перед FROM», «колонка не найдена, похожие: …».
- Указывать урок, который стоит повторить (через панель «Повторить»).
- Подходит для всех SQL-курсов. Делать после «SQL Advanced».

## Локальный чат «Спроси про SQL» (по желанию ученика)

- Маленькая модель работает в браузере (WebGPU/WASM: WebLLM, transformers.js
  или wllama). Запросы никуда не уходят.
- Веса (примерно 0,4–1 ГБ) лежат на Hugging Face, не в репозитории
  (лимит GitHub 100 МБ на файл). Скачиваются по кнопке, кэшируются в браузере.
- Отвечает только по текстам уроков: в вопрос подставляется нужный кусок
  теории. Вопросы вне SQL отклоняет.
- Риски: слабый русский, выдуманные ответы, медленно на телефонах.
- Сначала прототип на типичных вопросах учеников, потом решение.
  Делать после подсказчика ошибок.

## Вариант чата: модель на сервере

- Идея: не заставлять ученика скачивать веса, а отвечать на сервере.
- Переезд на Vercel + Neon для этого не нужен и не помогает: Vercel без GPU,
  у функций лимит около 250 МБ и короткий таймаут, Neon — это только Postgres.
  Модель всё равно живёт на отдельном сервере вывода (VPS с llama.cpp,
  Modal, Hugging Face Inference Endpoints).
- Плюсы: нет загрузки 0,4–1 ГБ, работает на телефонах, можно взять модель
  крупнее и ответы лучше. Минусы: постоянные расходы, нужна защита от
  злоупотреблений (вход, лимиты запросов), вопросы учеников уходят на наш сервер.
- Решать после прототипа локального чата: если качества маленькой модели
  не хватит, серверный вариант станет основным.

## Курс «Работа с проектом» (git и PR)

**Сделано:** курс «Git и проект» (вкладка «Git», 12 уроков), см. `openspec/changes/add-git-course/`.
Дальше по теме: конфликты при слиянии, `.gitignore`, ветка под каждую задачу,
скриншоты интерфейса GitHub и VS Code (только если попросят в отзывах), порядок feature → dev → preprod → main.

Объясняем, как устроена работа команды, и проходим путь на реальном проекте.
Создавать проект с нуля не нужно.

- Что такое проект (репозиторий) и зачем нужен git: история, откат, работа вдвоём.
- Частые команды: `add`, `commit`, `push`, `pull`, `switch` / `checkout`,
  `status`, `log`, `diff`. Что делает каждая и в каком порядке их применяют.
- Ветки: зачем они нужны, как создать, переключиться, влить; порядок
  feature → dev → preprod → main на примере этого проекта.
- Pull request: что это, как его открыть, проверить и влить; роль проверок (CI)
  и защищённых веток.
- Практика на реальном проекте: создать аккаунт на GitHub, клонировать
  репозиторий на свой компьютер, пройти путь «изменить файл → `add` → `commit`
  → `push`» и увидеть изменение в репозитории.
- Все действия показываем командами в bash (терминал). Не все пользуются
  VS Code, поэтому достаточно открыть любой текстовый файл в простом редакторе,
  отредактировать его и отправить состояние проекта в git.
- Формат: короткая теория с пояснением «зачем», вопросы в виде теста и
  пошаговое задание на реальном проекте.
