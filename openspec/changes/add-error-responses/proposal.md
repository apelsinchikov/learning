# Изменение: урок и практика про описание ошибок

## Зачем
Урок 5 обещает разобрать 400 и 409, урок 16 их перечисляет, но ни в одной
практике они не описываются. Итоговый API не содержит ошибок, кроме 404.
Аналитику нужно уметь описывать негативные сценарии.

## Что меняется
- Новый теоретический урок после «Коды ответов и ошибки» (текущий 16):
  «Как описать ошибку» — общая схема `Error` (`code`, `message`), ответы
  400 и 409, вынос повторяющегося ответа в `components/responses` и ссылка
  `$ref: '#/components/responses/...'`.
- Новая практика: добавить к `POST /users` ответы 400 и 409 со схемой `Error`,
  а к `GET /users/{id}` ссылку на общий ответ `NotFound`.
- Итоговый Users API (урок 18) требует ошибки в `POST /users`.
- Валидатор: поддержать проверку ссылок на `components/responses`.

## Не входит
- Подробности безопасности (401/403), кастомные заголовки ошибок, RFC 7807.

## Влияние
- Затронутые спецификации: `course-content`, `practice-validation`.
- Нумерация следующих уроков сдвигается на 2; сохранённый прогресс привязан к
  `id` урока, поэтому новые уроки получают новые `id` и не ломают его.
