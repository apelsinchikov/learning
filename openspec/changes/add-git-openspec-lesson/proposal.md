# Изменение: урок про OpenSpec в курсе «Git и проект»

## Зачем
Аналитик работает с требованиями, которые должны жить рядом с кодом: описаны,
согласованы и только потом реализованы. Для этого в проекте используется OpenSpec.
Ученику нужно понять, зачем он нужен, как подключить его к своему репозиторию и
кто на каком этапе что пишет: аналитик, разработчик, ИИ-ассистент.

## Что меняется
- Новая глава 5 «OpenSpec в проекте». В неё входят новый урок `git-openspec` и
  существующий итоговый урок `git-final` (переехал из главы 4).
- Урок `git-openspec`: зачем OpenSpec, папки `specs/` и `changes/`, четыре файла
  изменения (`proposal.md`, дельты в `specs/`, `design.md`, `tasks.md`), пример
  requirement и сценария, роли по этапам, установка Node.js и OpenSpec,
  `openspec init`, учебное изменение, отправка и pull request.
- Новые блоки уроков: `code` (текст без приглашения `$`) и `table` (строки-карточки
  с подписанными колонками, чтобы читалось на телефоне).
- Итоговый тест получил два вопроса про OpenSpec.

## Влияние
- Курс «Git и проект»: 13 уроков в 5 главах. Идентификаторы существующих уроков
  не менялись, прогресс сохраняется.
- Новых зависимостей и изменений в базе нет.

## Сверено с документацией OpenSpec
- Установка: `npm install -g @fission-ai/openspec@latest`, Node.js 22.12 или новее.
- `openspec init` создаёт `openspec/specs/`, `openspec/changes/`,
  `openspec/config.yaml` и инструкции для выбранных ассистентов;
  `--tools none` подключает без ассистента.
- Основной поток: `/opsx:explore` (по желанию), `/opsx:propose`, `/opsx:apply`,
  `/opsx:archive`. `/opsx:verify` входит в расширенный набор.
- При архивации дельты (`ADDED`, `MODIFIED`, `REMOVED`) вливаются в `specs/`, а
  папка изменения переезжает в `changes/archive/`.
