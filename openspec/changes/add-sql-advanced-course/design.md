# Дизайн: курс «SQL Advanced»

Для кого: системный аналитик. Он чаще пишет простые запросы, а сложные пишет
разработчик. Его работа: описать, **что откуда брать и какая структура должна
получиться**, прочитать чужой запрос и понять, что он делает, спроектировать
таблицы под метод API, проверить данные. Поэтому курс не про аналитику данных:
оконные функции (`RANK`, `LAG`, `PARTITION BY` и подобные) в основную часть не
входят, ровно один бонусный урок учит их **читать**.

Сюжет: через год после базового курса вы работаете в управляющей компании
«Перевала». Разработчик Тимур просит описать метод и схему, бухгалтерия ищет
расхождения, владелица просит выгрузки. Теории минимум, больше рабочих задач.

## Состав (28 уроков, 6 глав)

### Глава 1. Читаем схему и собираем данные
1. `sqa-schema-read` — читаем чужую схему: ключи, связи, что откуда брать (`dg-er-keys`, `sql-read-db`)
2. `sqa-api-query` — запрос под метод API: `GET /bookings` собираем из нескольких таблиц (`sql-three-tables`)
3. `sqa-cte` — `WITH`: запрос шагами, как черновик спецификации (`sql-subquery`)
4. `sqa-exists` — `EXISTS`, «у кого нет оплаты» (`sql-anti-join`)
5. `sqa-null-traps` — что значит «пусто» в требованиях: `NULL`, `COALESCE`, `LEFT JOIN` (`sql-null`, `sql-left-join`)

### Глава 2. Отчёты, фильтры и страницы
6. `sqa-report` — требование → запрос: выручка по месяцам (`sql-group-by`, `sql-having`)
7. `sqa-filters` — необязательные фильтры метода: диапазоны дат, поиск, `NULL` в параметре (`sql-where`, `sql-like`)
8. `sqa-paging` — страницы и порядок: `LIMIT/OFFSET`, стабильная сортировка, почему `OFFSET` тормозит (`sql-order-by`)

### Глава 3. Изменение данных: что делает метод
9. `sqa-insert` — `INSERT … RETURNING`: что происходит при `POST` (`201` и `id`)
10. `sqa-update` — `UPDATE`: `PUT` и `PATCH`, частичное обновление, `WHERE` сначала проверяем `SELECT`-ом
11. `sqa-delete` — `DELETE` и мягкое удаление (`deleted_at`), когда `409`
12. `sqa-upsert` — `ON CONFLICT`: повторный запрос не создаёт дубль (идемпотентность)
13. `sqa-tx` — транзакция: что в методе должно быть атомарным (`dg-method-db`)
14. `sqa-concurrency` — два запроса одновременно: блокировка и версия записи, `409` (читаем сценарии)

### Глава 4. Проектируем структуру
15. `sqa-ddl` — `CREATE TABLE`: типы, `NOT NULL`, `DEFAULT` (`dg-er-entities`)
16. `sqa-keys` — `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `ON DELETE` (`dg-er-keys`)
17. `sqa-check` — `CHECK` и справочники: статус строкой, `enum` или таблицей
18. `sqa-normal` — нормальные формы на примере «плохой» таблицы
19. `sqa-many-many` — связующая таблица в SQL (`dg-er-many-many`)
20. `sqa-history` — история и аудит: `created_at`, `updated_at`, таблица истории

### Глава 5. Данные между системами
21. `sqa-mapping` — маппинг «источник → приёмник»: `INSERT … SELECT`, приведение типов
22. `sqa-quality` — проверки качества: дубликаты, «сироты», пропуски
23. `sqa-migration` — миграция из плоской таблицы в нормализованную, `ALTER TABLE`
24. `sqa-views` — `VIEW` для отчётов и интеграций

### Глава 6. Скорость и итоговые кейсы
25. `sqa-index` — индекс по требованию: `EXPLAIN`, `Seq Scan` и `Index Scan`
26. `sqa-read-complex` — бонус: читаем чужой сложный запрос (CTE, подзапросы, одна оконная функция только на чтение)
27. `sqa-case-export` — кейс: выгрузка для бухгалтерии, от требования до проверок
28. `sqa-case-module` — кейс: новый модуль, от требований к схеме, запросу и методу API

Песочница: свободные запросы с записью (изменения откатываются).

## База «Перевал: сезон»
Таблицы: `guests`, `rooms`, `staff` (как в базовом курсе), `bookings`
(≈ 400 строк), `payments`, `services`, `booking_services`. Данные порождает
детерминированный генератор с фиксированным зерном, эталонные ответы стабильны.
Колонка `bookings.extras` типа `jsonb` нужна только для обсуждения в уроках
про схему. В уроках 15–20 ученик создаёт собственные таблицы.

## Состояние базы
Данные не накапливаются между запусками, но у каждого урока есть **своё
стартовое состояние**, описанное в самом уроке. Это либо чистая база курса, либо
база плюс скрипт `before` (например, в уроке 11 уже есть бронь из урока 9, а в
уроке 16 уже созданы таблицы из урока 15). Скрипт выполняется внутри того же
запуска перед запросом ученика. Так ученик видит в каждом уроке понятные данные,
а проверка не зависит от того, какие уроки он прошёл и в каком порядке.

## Схема базы под рукой
Ученик всегда должен видеть, к чему он пишет запросы.
- Вкладка «Схема» в правой панели (первая, открыта по умолчанию): таблицы,
  колонки, типы, ключи, связи.
- Кнопка «Схема целиком» открывает широкое окно: ER-диаграмма (Mermaid, строится
  автоматически из описания схемы тем же движком, что в «Диаграммах»), список
  таблиц и по клику первые строки таблицы.
- Схема показывает состояние базы **для текущего урока**: таблицы из `before` и
  созданные в задаче появляются сразу.
- Название таблицы в тексте урока кликабельно: раскрывает её в панели.

## Движок
Сейчас движок открывает базу в режиме `read only`. Для курса нужен второй режим:
- Каждый запуск выполняется внутри внешней транзакции, которая **всегда
  откатывается**. Запросы на изменение реально выполняются (видны `RETURNING` и
  проверочный `SELECT`), но их результат не попадает в следующий запуск.
- Команды `BEGIN`, `COMMIT`, `ROLLBACK`, ученика заменяются на `SAVEPOINT`,
  `RELEASE`, `ROLLBACK TO`, чтобы ученик не закрыл внешнюю транзакцию. Урок про
  транзакции объясняет это честно: «в песочнице всё откатывается».
- Запуск нескольких команд подряд: результат последней, а для `INSERT ... RETURNING`
  показываются возвращённые строки.
- Запрещено: `COPY`, `CREATE EXTENSION`, `DROP DATABASE`, `SET` ролей. Время
  выполнения ограничено, зависший запрос прерывается.
- Задачи на изменение данных проверяются так: выполнить запрос ученика, затем
  проверочный `SELECT` из задачи, сравнить с эталоном. Задачи на индексы и
  `EXPLAIN` проверяют текст плана (есть ли узел `Index Scan`).

Риск: поведение `SAVEPOINT`-подмены и `MERGE` в версии PGlite нужно проверить
коротким экспериментом до написания уроков главы 3.

## Окно-подсказка «Повторить»
Выдвижная панель справа (на телефоне шторка снизу на весь экран), не закрывающая
задачу и редактор. Подробности и порядок работы в `specs/lesson-peek/spec.md`.

Содержимое берётся из данных урока другого курса:
- «Коротко»: записи `cheat` урока (шпаргалка) и первый пример;
- «Полностью»: блоки `theory` без задачи и сюжета, примеры только для чтения
  с кнопкой «Скопировать».

Ссылка в данных урока: поле `refs: ["sql-inner-join"]` и разметка в тексте
`[[sql:sql-inner-join|JOIN ON]]`. Компонент общий: «Диаграммы» и OpenAPI тоже
смогут ссылаться на уроки соседних курсов.
