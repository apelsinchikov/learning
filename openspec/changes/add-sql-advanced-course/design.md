# Дизайн: курс «SQL: продвинутый»

Сюжет: через год после истории из базового курса вы работаете в управляющей
компании «Перевала». Владелица Ольга Сергеевна просит цифры к сезону, бухгалтерия
ищет расхождения, а разработчик Тимур просит помочь со схемой и скоростью. Теории
минимум, больше рабочих задач.

## Состав (28 уроков, 6 глав)

### Глава 1. Сложные запросы
1. `sqa-cte` — `WITH`: разбить длинный запрос на шаги (повторить: `sql-subquery`)
2. `sqa-exists` — `EXISTS`, `NOT EXISTS`, коррелированные подзапросы (`sql-anti-join`)
3. `sqa-set-ops` — `INTERSECT`, `EXCEPT`, `UNION ALL` (`sql-case-union`)
4. `sqa-lateral` — `LATERAL` и «последние N на каждого» (`sql-top-n`)
5. `sqa-recursive` — рекурсивный CTE: цепочка руководителей (`sql-self-join`)

### Глава 2. Оконные функции
6. `sqa-over` — `OVER()`: итог рядом со строкой (`sql-group-by`)
7. `sqa-partition` — `PARTITION BY`: доля в группе, отклонение от среднего
8. `sqa-rank` — `ROW_NUMBER`, `RANK`, `DENSE_RANK`: топ-N в группе (`sql-order-by`)
9. `sqa-lag-lead` — `LAG`, `LEAD`: сравнить с прошлым периодом
10. `sqa-frame` — нарастающий итог и скользящее среднее (`ROWS`, `RANGE`)

### Глава 3. Время, строки, JSON
11. `sqa-dates` — `date_trunc`, интервалы, `extract` (`sql-alias`)
12. `sqa-series` — `generate_series`: дни без броней в отчёте (`sql-left-join`)
13. `sqa-strings` — `regexp_replace`, `split_part`, `string_agg` (`sql-like`)
14. `sqa-json` — `jsonb`: `->`, `->>`, разворот массива

### Глава 4. Изменение данных
15. `sqa-insert` — `INSERT`, `RETURNING`, значения по умолчанию
16. `sqa-update-delete` — `UPDATE`, `DELETE` и привычка проверять `WHERE` сначала `SELECT`-ом
17. `sqa-upsert` — `ON CONFLICT`, `MERGE`
18. `sqa-tx` — `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT` (диаграмма `dg-method-db`)
19. `sqa-isolation` — изоляция и блокировки: читаем сценарии, ищем аномалию

### Глава 5. Схема и целостность
20. `sqa-ddl` — `CREATE TABLE`, типы, `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `CHECK` (`dg-er-keys`)
21. `sqa-normal` — 1–3 нормальные формы: разбираем «плохую» таблицу
22. `sqa-views` — `VIEW` и `MATERIALIZED VIEW`

### Глава 6. Скорость и итоговые кейсы
23. `sqa-explain` — читаем план `EXPLAIN`
24. `sqa-index` — индекс: когда помогает (план меняется на `Index Scan`), когда нет
25. `sqa-antipatterns` — `SELECT *`, функция на колонке, `OR`, N+1: переписать запрос
26. `sqa-case-funnel` — кейс: воронка и конверсия
27. `sqa-case-cohorts` — кейс: когорты, удержание, ABC-анализ
28. `sqa-final` — отчёт для владелицы: один запрос на 5 таблиц

Песочница: свободные запросы с записью (изменения откатываются).

## База «Перевал: сезон»
Таблицы: `guests`, `rooms`, `staff` (как в базовом курсе, для иерархии),
`bookings` (≈ 400 строк), `payments`, `services`, `booking_services`,
`booking_events` (воронка). Данные порождает детерминированный генератор с
фиксированным зерном, поэтому эталонные ответы стабильны. Таблица
`bookings.extras` хранит `jsonb` для урока про JSON.

## Движок
Сейчас движок открывает базу в режиме `read only`. Для курса нужен второй режим:
- Каждый запуск выполняется внутри внешней транзакции, которая **всегда
  откатывается**. Изменения не попадают в следующий запуск.
- Команды `BEGIN`, `COMMIT`, `ROLLBACK`, ученика заменяются на `SAVEPOINT`,
  `RELEASE`, `ROLLBACK TO`, чтобы ученик не закрыл внешнюю транзакцию. Урок про
  транзакции объясняет это честно: «в песочнице всё откатывается».
- Запуск нескольких команд подряд: результат последней, а для `INSERT ... RETURNING`
  показываются возвращённые строки.
- Запрещено: `COPY`, `CREATE EXTENSION`, `DROP DATABASE`, `SET` ролей. Время
  выполнения ограничено, зависший запрос прерывается.
- Задачи на изменение данных проверяются так: выполнить запрос ученика, затем
  проверочный `SELECT` из задачи, сравнить с эталоном. Задачи на индексы и
  `EXPLAIN` проверяют текст плана (есть ли узел `Index Scan`).

Риск: поведение `SAVEPOINT`-подмены и `MERGE` в версии PGlite нужно проверить
коротким экспериментом до написания уроков 17–19.

## Окно-подсказка «Повторить»
Выдвижная панель справа (на телефоне шторка снизу на весь экран), не закрывающая
задачу и редактор. Подробности и порядок работы в `specs/lesson-peek/spec.md`.

Содержимое берётся из данных урока другого курса:
- «Коротко»: записи `cheat` урока (шпаргалка) и первый пример;
- «Полностью»: блоки `theory` без задачи и сюжета, примеры только для чтения
  с кнопкой «Скопировать».

Ссылка в данных урока: поле `refs: ["sql-inner-join"]` и разметка в тексте
`[[sql:sql-inner-join|JOIN ON]]`. Компонент общий: «Диаграммы» и OpenAPI тоже
смогут ссылаться на уроки соседних курсов.
