# Спецификация: вход в аккаунт

## Purpose
Необязательный вход через Google или Яндекс для сохранения прогресса.

## Requirements

### Requirement: Вход необязателен
Курс SHALL быть полностью доступен без входа. Вход нужен только для сохранения
прогресса в облаке и переноса между устройствами.

#### Scenario: Гость
- **WHEN** посетитель не входил
- **THEN** все уроки и практики работают, прогресс хранится в его браузере

### Requirement: Способы входа
Система SHALL предлагать вход через Google и через Яндекс (custom OAuth-провайдер
`custom:yandex` в Supabase). Пароли и коды на почту SHALL NOT использоваться.
Набор способов задаётся списком провайдеров в `src/auth/config.js`; провайдер
можно скрыть флагом `enabled: false`.

#### Scenario: Окно входа
- **WHEN** гость нажимает «Войти»
- **THEN** открывается окно с кнопками «Войти через Google» и «Войти через Яндекс»

#### Scenario: Ошибка провайдера
- **WHEN** провайдер вернул ошибку
- **THEN** окно показывает понятное сообщение, повторная попытка возможна

### Requirement: Схема входа
Вход SHALL выполняться через OAuth по схеме PKCE (`signInWithOAuth`), с возвратом
на адрес курса. После возврата служебные параметры (`code`, `error*`) SHALL
удаляться из адресной строки.

#### Scenario: Двойной клик
- **WHEN** пользователь дважды нажимает кнопку провайдера
- **THEN** запускается только один вход

### Requirement: Яндекс и email
Яндекс не отдаёт `email` в формате, понятном Supabase, поэтому адрес пользователя
SHALL запрашиваться через Edge Function `yandex-userinfo`, которая преобразует
ответ (`default_email → email`, `id → sub`). Функция SHALL быть без проверки JWT.

#### Scenario: Первый вход через Яндекс
- **WHEN** пользователь входит через Яндекс впервые
- **THEN** в Supabase появляется пользователь с email, именем и провайдером
  `custom:yandex`

### Requirement: Выход
Выход SHALL сначала сохранять несохранённый прогресс, затем завершать только
локальную сессию (`scope: local`) и возвращать интерфейс в гостевое состояние.

#### Scenario: Выход
- **WHEN** пользователь нажимает «Выйти»
- **THEN** кнопка меняется на «Войти», локальный кэш прогресса очищается,
  открывается первый урок

### Requirement: Безопасность
Подписанная сессия SHALL храниться клиентом Supabase. Приватные секреты
(Client Secret провайдеров) SHALL храниться только в настройках Supabase.
В коде SHALL использоваться только публичный (publishable) ключ.

#### Scenario: Репозиторий
- **WHEN** проверяется репозиторий
- **THEN** в нём нет Client Secret, service-role ключей и паролей

### Requirement: Колбэк без взаимоблокировки
Обработчик смены авторизации SHALL NOT вызывать Supabase синхронно внутри
`onAuthStateChange`: вызов откладывается (`setTimeout`), иначе выход «зависает».

#### Scenario: Нажатие «Выйти»
- **WHEN** пользователь выходит
- **THEN** интерфейс обновляется, а не остаётся без изменений
